## The package index lasts 90 days

The project's package index was signed for 30 days and renewed by a
weekly job. GitHub stops a scheduled job after 60 days without activity
in the repository, so a quiet repository would have left every installed
system's `pkg update` refusing an expired index. Now:

- **`INDEX.90`**, signed for 90 days, sits beside the 30-day `INDEX`;
  both carry the same serial. This release's `pkg` reads `INDEX.90`
  first, and `INDEX` only when the server has no `INDEX.90`. Both are
  checked in the same way, and a replayed index is still refused.
- **Every release and pre-release signs both again**, as the weekly job
  does, and the release checklist starts the job by hand after a quiet
  month.
- **An expired index is refused with one sentence**, which names its
  expiry and serial and says that the repository must be signed again.
  `pkg` exits non-zero and keeps the stored index.

**Systems on v1.0.6 need no action** beyond their next `pkg update`. They
keep reading the 30-day `INDEX`, which is still signed weekly and at
every release. After moving to this release they read `INDEX.90`.

An installed system's `/tmp` is now mode 01777, so every user can write
there. It was 0755, owned by root.

## Fixes from the Parallels test

- **A large read is filled.** `dd if=/dev/zero bs=1M count=4` copies
  four whole records. A read of a regular file or `/dev/zero` used to
  stop at 64 KiB. The read is one operation: another reader or a seek
  on the same open file never lands in the middle of it.
- **`wget` refusing a certificate** now ends on the TLS library's reason.
  Before, it added `wget: error getting response: Resource temporarily
  unavailable`.
- **No free-count warning at mount**: every mount of a cleanly unmounted
  disk warned that the superblock's free count differed from the
  bitmap's. The comparison now runs before the free-log replay, not after
  it.
- **A Linux program's `writev` is one write**, as on Linux: a line a
  program prints is no longer split on the console by a kernel message,
  and a datagram socket sends the vector as one datagram.
- **`sftp`'s `?` link count is not a defect.** It is how OpenSSH's own
  client renders a long listing, as on Linux; the file's count on the
  server is right (`stat -c %h`).

## Shared libraries

Linux programs can now be dynamically linked against musl:

- **`/lib/libc.so`**, which is also musl's dynamic linker, with
  `/lib/ld-musl-x86_64.so.1` (or `ld-musl-aarch64.so.1`) linking to it.
  This is the interpreter every dynamic program names. `dlopen`, `RUNPATH`
  and thread-local storage work. Libraries load at random addresses on
  every run.
- **`/bin/busybox.dyn`** is BusyBox dynamically linked, with a link for
  each applet under `/usr/bin`. It passes the same scripted test and
  BusyBox testsuite as the static `/bin/busybox`, which stays the shell.
  `/bin` comes first in `PATH`, so nothing changes until you ask for it:

  ```text
  cosmo$ /bin/busybox.dyn sh -c 'echo hello from a dynamic shell'
  cosmo$ PATH=/usr/bin:$PATH ls -l /lib
  ```

  The package `busybox-dyn` installs the same binary.
- **The kernel tells the linker the truth.** `AT_SECURE` is set when the
  effective ids are not the real ones, and musl then ignores
  `LD_LIBRARY_PATH` and `LD_PRELOAD`. `AT_HWCAP` and `AT_HWCAP2` carry
  the CPU's features. `stat` reports a device number per mount.
- **Text relocations are refused.** A library that needs writable,
  executable code cannot load under W^X, and the kernel log says to
  build it `-fPIC`.
- **`pkg` knows libraries.** A package records the libraries it provides
  and requires. `pkg install` refuses a package whose library nothing
  provides. `pkg remove` refuses to remove a library another package
  still needs.

Native CosmoOS programs stay static.

## Upgrading from v1.0.6

Run `cosmo-upgrade --fetch v1.0.7` twice. The first run is v1.0.6's
program, which does not know `/lib`. It installs everything else,
including the new `cosmo-upgrade`. The second run uses that new program:
it finds the set already current, finishes, and adds `/lib`. Then reboot
and run `pkg update && pkg upgrade`. Without the second run the system
works, but `/bin/busybox.dyn` cannot start. From v1.0.5 and earlier,
follow the guide's "Fetching directly" page with this release's package.
Its `cosmo-upgrade` installs `/lib` in one run.

Tested: on every change and on both architectures, `make test-busybox`
(the static and the dynamic BusyBox, `dlopen`), `make test-pkg-net` (the
expiry sentence, `INDEX.90` and the fallback to `INDEX`), `make
test-install` (`/tmp`, no free-count warning) and `make test-net-login`
(the refused certificate, `sftp`).
