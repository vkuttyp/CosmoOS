# CosmoOS 1.1.1

A landing terminal: the screen draws colours, the console opens on a
welcome screen with the machine's facts, and an installed system asks
for root's password before it gives a shell.

## The console logs in

**An installed system's console now asks for a login.** This is the
change to plan for when upgrading:

- At the first boot after an install or an upgrade, the console asks you
  to choose root's password (typed twice, nothing shown). From then on
  every boot ends at a login screen with the release, the machine's name
  and its address; log in as `root`.
- `exit` logs out and brings the login screen back. `poweroff` turns the
  machine off.
- The password is kept hashed (SHA-512) in `/etc/shadow`, which only
  root reads. `passwd` changes it.
- ssh is unchanged: root, by key only. The password does not log in over
  ssh, and the ssh server starts whether or not anyone has answered the
  console.
- The serial port is the same console: whoever is at it sees the login
  too.
- The live image, the one you install from, asks for nothing: it has no
  accounts.

## The welcome screen

After a login (and on the live image at boot) the console clears and
shows the CosmoOS logo with the machine's facts beside it: user and
host, release, uptime, installed packages, shell, console size, CPUs,
memory and address, and a line of commands to start with. The prompt is
`cosmo$` as before. `cosmo-welcome` shows it again; it is not shown over
ssh.

## Colours on the screen

The framebuffer console (a virtual machine's window) obeys the escape
sequences programs write, where it used to draw them as text:

- sixteen foreground and background colours and bold (`ESC [ ... m`);
- clearing the screen, erasing to the end of a row;
- placing and moving the cursor.

Other sequences are read to their end and draw nothing. There is no
256-colour or true-colour mode, underline, reverse video or scroll
region. The serial port passes a program's escapes on as written.

## Upgrading from v1.1.0

`cosmo-upgrade --fetch v1.1.1`, reboot, then `pkg update && pkg
upgrade`. At the first boot the console asks for root's password (see
above); a machine you reach only by ssh keeps working without it.
`cosmo-upgrade --rollback` returns to v1.1.0.

Known: `passwd` prints `can't lock '/etc/shadow': Invalid argument`
before it changes the password; the password is changed.

Tested:

- On every change, on both architectures: `make test-install` installs
  this build, chooses the password at its first boot, logs in, and
  checks that a wrong password is refused; `make test-display` reads a
  coloured word's pixels off the screen; `make test-upgrade` upgrades a
  published release to this build and rolls back.
- On a Parallels virtual machine upgraded from v1.1.0 to v1.1.1-rc1
  before this release was tagged. See
  [Tested platforms](../guide/platforms.md).
