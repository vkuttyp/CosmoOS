## pkg and cosmo-upgrade fetch directly

An installed system now updates over the network, with nothing to fetch
by hand:

```text
cosmo$ pkg update && pkg upgrade
cosmo$ cosmo-upgrade --check
cosmo$ cosmo-upgrade --fetch v1.0.7
```

- **The project's repository and release index** are published on GitHub
  Pages, `https://vkuttyp.github.io/CosmoOS/`: each architecture's package
  repository under `repo/ARCH/`, each release's upgrade set under
  `releases/TAG/` (without the images), and `releases/LATEST`. A fresh
  install's `/etc/pkg/repos.conf` names the network repository after the
  disk's own; `/etc/cosmo-release.conf` names the release index.
- **HTTPS with the certificate checked**: both programs run
  `/bin/cosmo-fetch`, which makes the same checks as `wget` (the server's
  certificate must chain to the Mozilla CA bundle in
  `/etc/ssl/certs/ca-certificates.crt`, be valid now, and name the host),
  all before it sends a request. A `repos.conf` line can also pin the
  server's key (`pin sha256:HEX`). Plain `http://` is refused unless the
  line says `insecure`. Redirects are followed only to the same host.
  Transfers that are cut resume.
- **A fresh index or none**: a network repository's index carries a
  serial number, a publication time and an expiry (at most 30 days). `pkg
  update` refuses one older than the last it accepted (a replay), and one
  that has expired, so an attacker who can only replay old signed files
  cannot hold back an update for long. The project re-signs its index
  weekly. A clock before the index's publication is reported with a hint
  (`date -s`), not accepted. A repository that cannot be reached is only
  a warning; the disk's packages still install.
- **`cosmo-upgrade --fetch TAG`** fetches the release's `SHA256SUMS` and
  its signature first, checks them against `/etc/pkg/keys`, then fetches
  the four set files and upgrades exactly as from a directory, with every
  check made again. `cosmo-upgrade --check` says whether a newer release
  is published.
- **Privileges**: `pkg install`, `upgrade` and `remove` need the
  `sys_admin` privilege; `pkg update`, `search`, `info` and `list` do not.

## Upgrading from v1.0.5 and earlier

These releases have no `cosmo-fetch`. Fetch this release's
`cosmoos-ARCH-cosmo-upgrade.cpk` (`ARCH` is `x86_64` or `aarch64`) with `wget` from
`https://vkuttyp.github.io/CosmoOS/releases/v1.0.6/`, check it with `pkg
install -n`, unpack `sbin/cosmo-upgrade` and `bin/cosmo-fetch`, and run
`COSMO_FETCH=./bin/cosmo-fetch ./sbin/cosmo-upgrade --fetch v1.0.6`
(the guide's "Upgrading" page, "Fetching directly"). Afterwards add the
network repository to the `/etc/pkg/repos.conf` the older installer
wrote: the first line on x86-64, the second on AArch64 (one of them):

```text
cosmo$ echo 'cosmoos https://vkuttyp.github.io/CosmoOS/repo/x86_64' >> /etc/pkg/repos.conf
cosmo$ echo 'cosmoos https://vkuttyp.github.io/CosmoOS/repo/aarch64' >> /etc/pkg/repos.conf
```

Tested: `make test-pkg-net` on x86-64 and AArch64, on every change. The
installed system runs against repositories the test serves over HTTPS:
it refuses untrusted, expired and misnamed certificates with no request
sent, and refuses a changed package, an index signed by another key, and
a replayed or expired index. It installs and upgrades from the served
repository, fetches a release set with `cosmo-upgrade`, and then runs
`pkg update` against the published repository itself.
