# CosmoOS 1.0.11

## Mirrors that survive a disk

**The installer can put the root on two disks.**

```text
cosmo$ cosmo-install vdc --mirror vdd
...
cosmo-install: the root is mirrored on vdc2 and vdd2 (vdd's root partition, partuuid ...)
```

Both disks get the same layout and their own EFI System Partition, so
either can boot. The root is one pool kept as two copies.

**When a disk fails or is pulled, the system keeps running.**

- The kernel says so once:

  ```text
  pool: cosmo-root: member 0 copy 1 (vda2) MISSING (-19): the member is degraded
  ```

- `/proc/mounts` shows `rw,degraded`.
- `cosmo-pool status` says `DEGRADED` and how much the missing copy
  missed.
- A boot with a copy missing still boots, and init says so.
- I/O that no copy can satisfy fails with `EIO`; it is not a panic.

**`cosmo-pool` replaces a disk, and a spare takes over by itself.**

- `cosmo-pool replace 0:1 vdb` puts a new disk in a missing copy's
  place.
- The new copy is **resilvered** while the system runs. Every block the
  pool uses is copied to it at most `fs.resilver_rate` blocks a second
  (8192, 32 MiB/s, unless set). Every write goes to it meanwhile, and a
  reboot resumes where the resilver stopped.
- A disk that was pulled and comes back while the pool stays mounted is
  caught up from the pool's record of what it missed, rather than
  rebuilt. One that was missing when the pool was mounted is rebuilt
  whole.
- The other subcommands: `status`, `offline`, `online`, `attach` (make a
  single disk a mirror), `detach`, `add-spare` and `remove-spare`.
- A spare takes the place of a copy that fails or whose disk goes, with
  no command.
- A copy that fails more than `fs.fault_errors` times (16) is taken out
  as `FAULTED`.

**Disks can be pulled and added while the system runs.** PCIe native
hotplug works on both architectures: removal through the slot's
attention button, and insertion with the disk's partitions read. This
covers virtio-blk and NVMe behind PCIe root ports.

See the guide's new page, [Mirrors](../guide/mirrors.md).

## Fixes

- **Every copy of a mounted mirror counts as in use.** `/dev/blkctl`
  and `mkfs` refuse a device that another copy of a mounted pool
  stands on, not just the device the pool was mounted from.
- **Devices behind a PCIe root port get their DMA mapping.** This
  applies to VT-d's bridge scopes and to SMMUv3 stream ids above 255.

## The pool's format

A pool is raised to format 13 the first time it has a copy to record,
which is when a mirror is degraded. CosmoOS 1.0.10 and older cannot
mount a pool at format 13. A pool that is never degraded keeps its
format.

## Upgrading from v1.0.10

`cosmo-upgrade --fetch v1.0.11`, reboot, then `pkg update && pkg
upgrade`. The upgrade takes a boot environment, so `cosmo-upgrade
--rollback` returns the root and the boot set as they were. A root pool
that has been degraded under 1.0.11 is at format 13, and the rolled-back
1.0.10 kernel cannot mount it.

`cosmo-upgrade` writes the new release to the ESP of the disk the
system booted from only. On a mirrored root, the other disk's ESP keeps
the release it was installed with.

Tested:

- On every change, on both architectures, beside the release tests:
  - `make test-mirror`: install onto two disks; pull one under a writer;
    replace and resilver it; scrub; reboot from the new pair; let a
    spare take over; boot with a copy missing, and resilver it on its
    return.
  - `make test-pci-hotplug`.
- On a Parallels virtual machine, upgraded from v1.0.10 to v1.0.11-rc1
  before this release was tagged. What its mirror did there is in
  [Tested platforms](../guide/platforms.md).
