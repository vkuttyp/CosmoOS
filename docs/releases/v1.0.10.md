# CosmoOS 1.0.10

## fsck at boot and `scrub --repair`

**The root is checked on every boot, before it is mounted.** Init runs
the kernel's own structural check on the root's pool, read-only, and
prints one line:

```text
cosmofs: root checked, 0 findings, 0 repaired
```

What a crash or a bookkeeping slip leaves is repaired without asking:
blocks allocated that nothing uses, a wrong total, a stale rollback
record or hold, a snapshot's identity -- and, named by inode on the
console, an inode no name reaches or a wrong link count. Anything else is
a question about which of two things is real, and the boot does not
answer it: the root is refused, the class is named, and you are left at
the live system's shell with the pool unmounted and the command to run:

```text
cosmofs: root refused: cross-linked; vda2 is not mounted. From this shell: fsck.cosmofs --repair vda2
```

`fsck=check` on the kernel command line reports and repairs nothing;
`fsck=skip` does not check.

**`fsck.cosmofs` checks a pool nothing has mounted.** `fsck.cosmofs
--check DEVICE` writes nothing; `--repair` repairs what has one right
answer -- including, offline only, a block in use that the allocator
calls free -- and reports the rest. It is the kernel's checker, through
`/dev/fsctl`, not a copy of it. Its output names each finding with its
class, the block or inode and what was done, one line each, and its exit
status is fsck's: 0 nothing found, 1 all repaired, 4 findings left, 8
could not check.

**`fsctl scrub` reports; `fsctl scrub --repair` repairs.** The scrub
reads every block of every tree -- the live one and each snapshot's --
on every copy, and on a mirror rewrites a bad copy from a good one only
when asked. It reads at most `fs.scrub_rate` blocks a second (4096,
16 MiB, unless set with `sysctl`) and steps aside between tenths of a
second, so the programs using the pool keep going. `mkfs.cosmofs --mirror
A B` makes a two-way mirror.

See the guide's new page, [Checking and repairing](../guide/checking.md).

## Fixes

- **A read-only mount writes nothing.** Mounting a cosmofs read-only used
  to write the replay of what the last commit freed, or of inodes deleted
  while open, at unmount; it now does that in memory only.
- **A root that is not a directory is refused, not a panic.** One changed
  mode byte on a disk stopped the kernel when the root was mounted.
- **An allocation that fails no longer throws away the open
  transaction.** A file whose extent map needed a new block, or an
  inode's map path, at a moment memory was short failed every change
  after it until the next unmount; the operation now fails alone and can
  be retried.
- **Older-format pools stay readable by their kernels:** a pool below
  format 6 no longer gets compressed records.
- **The scrub's counts reach you when it finds damage**, and it no longer
  reports blocks it is still writing as unrecoverable.
- **A rollback left pending says why.** When the mount could not apply a
  pending rollback (no room), init's line now ends with the reason.

## Upgrading from v1.0.9

`cosmo-upgrade --fetch v1.0.10`, reboot, then `pkg update && pkg
upgrade`. The upgrade takes a boot environment, so `cosmo-upgrade
--rollback` returns the root and the boot set as they were. The first boot
of v1.0.10 checks the root before it mounts it; a root an older kernel left
with findings a boot may repair is repaired then, and the line says so.

Tested: on every change, on both architectures, `make test-fsck` (the
installed root damaged 23 ways and booted; scrub `--repair` on a mirror)
beside the release tests; and on a Parallels virtual machine, upgraded from
v1.0.9 to v1.0.10-rc1 before this release was tagged.
