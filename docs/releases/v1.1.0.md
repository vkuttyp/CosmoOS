# CosmoOS 1.1.0

The first release since v1.0.14. It has a C compiler on the system, longer
file names, hard links, nice values, and a kernel of which half is now
written in CeeSafe, a memory-safe language that compiles to C.

## A C compiler on the system

`cc` is TinyCC, with musl's headers, start files and libraries under
`/usr`. It builds static and dynamic programs and programs that use
`dlopen`:

```text
cosmo$ cat > hello.c
#include <stdio.h>
int main(void) { puts("hello"); return 0; }
cosmo$ cc -o hello hello.c && ./hello
hello
```

`make test-selfhost` (CI, both architectures) runs it on the installed
system: TinyCC's own test suite passes, and TinyCC rebuilds itself from
its source to the same bytes. A program larger than 16 MiB is still
refused at exec, so clang and lld do not run.

## Files

- **Names up to 255 bytes.** The limit was 47. A pool takes cosmofs
  format 15 when the first name over 47 bytes is made in it. **From
  then on v1.0.14 and older cannot mount that pool**, so a rollback to
  v1.0.14 must be made before such a name exists.
- **Hard links.** `ln` without `-s` works; a file's data goes when its
  last name does.
- Native programs can set a file's mode, owner and times, and creation
  takes the umask.

## Processes and time

- **Nice values.** `nice`, `renice` and `ps -o nice`. Programs at the
  default priority share a CPU by Linux's weights: nice 0 against nice 5
  gets about three times the CPU.
- **CPU time is measured.** `time`, `getrusage`, `times` and
  `/proc/<pid>/stat` report user and system time. Before this release
  `CLOCK_PROCESS_CPUTIME_ID` and `CLOCK_THREAD_CPUTIME_ID` read the
  wall clock, and a process lost the CPU time of a thread that had
  exited.
- `ITIMER_VIRTUAL` and `ITIMER_PROF` deliver `SIGVTALRM` and `SIGPROF`.

## A quiet screen

A machine with a display (a virtual machine's window) no longer scrolls
the kernel's log past at boot. The screen shows the kernel's errors and
what programs print: init's lines, the login, the shell. Every line is
still on the serial port and in `dmesg`. An image built with `verbose`
on its command line (`make CMDLINE='root=boot-disk verbose' image`)
shows the log on the screen as before.

## Security

- The kernel and its modules are built with a stack protector: a
  buffer overrun that reaches a return address stops the system with a
  panic that names it.
- A Linux program's signal trampoline is no longer at a fixed address.
- The secret behind TCP SYN cookies is drawn again once the random pool
  is seeded.

## Fixed

- With many packages installed, `pkg` read only part of its database
  (128 of 130 records in the test); `pkg upgrade` now plans every one.

## The kernel in CeeSafe

52% of the code that runs in ring 0 is now CeeSafe (132,614 lines),
against none in v1.0.14. That includes the whole system-call layer, both
the native one and the Linux one, except one table. The compiler,
ceesafec, turns each source into C at build time. A conversion is meant
to change no behaviour; the differences found are listed in the dated
reports under `docs/audit/`.

## Upgrading from v1.0.14

`cosmo-upgrade --fetch v1.1.0`, reboot, then `pkg update && pkg
upgrade`. `cosmo-upgrade --rollback` returns to v1.0.14 as long as no
file name over 47 bytes has been made (see Files).

Tested:

- On every change, on both architectures: `make test-upgrade` installs
  the published v1.0.14, upgrades it to this build with v1.0.14's own
  `cosmo-upgrade`, boots it, and rolls back to v1.0.14.
- On a Parallels virtual machine upgraded from v1.0.14 to v1.1.0-rc2
  before this release was tagged. See
  [Tested platforms](../guide/platforms.md).
