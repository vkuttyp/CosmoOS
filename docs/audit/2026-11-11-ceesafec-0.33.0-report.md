# ceesafec 0.33.0: the pin moves from 0.24.2, 2026-11-11

Roadmap 1.3's K stream writes the kernel's remaining C tables in CeeSafe, which needs CeeSafe's ADR 0091 (read-only
C objects: a `static` of an imported C type, emitted `const`, and `[i: e]` array literals), released as ceesafec
0.33.0 on 2026-11-11. This PR moves the pin and nothing else: no CeeSafe source changes, and no kernel C.

## Scope and baseline

Branch `pin-ceesafec-0.33.0` from main at `93cb4738` (#510).

## Audit (main at `93cb4738`, read, not copied)

| Item | Where | What it means |
|---|---|---|
| `CEESAFEC_VERSION = "0.24.2"` | `scripts/cee-gen.py` | the build refuses any other ceesafec |
| The runtime files the build takes from ceesafec's output are `rt.h`, `foreign.h` and `ceesafe_rt_core.c` | `scripts/cee-gen.py` `RUNTIME` | since ceesafec 0.27 `rt.h` includes `embed.h` from beside itself; without it every port fails with `rt.h:875: 'embed.h' file not found` |
| CI installs the Linux x86-64 release and checks its SHA-256 | `ci/Dockerfile`, `.github/workflows/ci.yml` | both carry the version's checksum |
| Other sessions replace `~/.ceesafe/bin/ceesafec` | the owner's machine | the matrix ran with `CEESAFEC` set to a kept copy of 0.33.0 |

## What changed

- **The pin** (`scripts/cee-gen.py`, `ci/Dockerfile`, `ci.yml`, the install lines in `docs/build/ceesafe.md` and
  `design.md`): 0.33.0, Linux x86-64 SHA-256 `165b975e51aad7565844378a205ad1ece002d5baed9b7e131bbc8456298c2f86`.
- **`embed.h`** joins `RUNTIME`, generated to `kernel/include/ceesafe/embed.h` as `rt.h` and `foreign.h` are.
- **`docs/roadmap-1.3.md`**: the pin's line.
- **`docs/testing/flakes.md`**: two entries from this validation (below).

No `.cee` file changed: every source that 0.24.2 accepted, 0.33.0 accepts, and `make cee-check` reports "172
generated files under out/cee match their CeeSafe sources (ceesafec 0.33.0)" with the one negative source refused as
its annotation says. Both architectures build debug and release with no warning.

Two steps did not pass the first time; both are recorded in `docs/testing/flakes.md` with their log facts.

- **Host test `online-late`** (`tests/host/test_quiesce.c:425-426`) failed once, in a first run of the matrix
  that was discarded for a script error, while this machine's load average was above 50 (a CeeSafe test suite was
  running). Three reruns at a load near 10 passed, as did the matrix's own run in the table.
- **AArch64 debug `make test` at `QEMU_SMP=2`** ran 2.2 times slower than its rerun from start to finish (525
  self-tests in 337.0 s; 152.8 s in the rerun), and so failed `process-user`'s 15-second bound (35.3 s), the
  40-second watchdog and the 380-second boot budget. The load average was 11.8 when it started and its 5-minute
  figure was 24.9 when it ended; what loaded the machine was not identified. The boots before and after it (165.5 s
  and 184.0 s of self-tests) passed.

No budget was changed.

## What this does not do

It uses nothing 0.33.0 adds. The first use is `kernel/syscall/native.c`'s call table (roadmap 1.3, K1).
