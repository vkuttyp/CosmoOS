# novac 0.3.1: static mutexes and object caches in Nova, 2026-10-29

Nova's 0.3.0 release carries its ADR 0026 (inline atomics), a code-generation change that clang's analyzer follows,
and ADR 0027: `here` in static initialisers, a static `Mutex`, moves through raw pointers and `ObjectCache<T>`. This
PR moves the pin, adds the C macro the static mutex needs, and extends the boot self-test `nova-kcore`. Its first
boot found a bug in Nova's library, fixed in the point release 0.3.1.

## Scope and baseline

Branch `novac-0.3.1` from main at `4802226e` (#489).

## Audit (main at `4802226e`, read, not copied)

| Item | Where | What it means |
|---|---|---|
| `mutex_init` sets the lock, owner, name, class, `pi_active`, `handoff`, and makes `pi_link` and the wait queue's two lists point to themselves | `kernel/scheduler/mutex.c:13`, `wait.c:16`, `spinlock.c:30`, `list.h` | what a static initialiser must reproduce |
| `LIST_HEAD_INIT(name)` and `WAITQUEUE_INIT(name)` take the object's own name | `list.h:21`, `wait.h:58` | self-pointers need the object's address |
| `kmem_cache_create` refuses an alignment that is not a power of two or is below `KMALLOC_MIN_ALIGN` (16); 0 asks for it | `kernel/memory/slab.c` `cache_setup` | what a typed cache must pass |
| Four analyzer reports in `kcore_test.c` are baselined (#489) | `tools/analysis/*.json` | removable once Nova's C no longer causes them |

## What changed

- **The pin, novac 0.3.1** (`scripts/nova-gen.py`, CI's checksum, the install lines). `make nova` regenerates every
  port: the runtime's atomics are now static inline in `rt.h`, and enum values whose payload may hold a pointer are
  built by small constructors in each port's C.
- **`MUTEX_INIT_AT(p, name)`** in `kernel/include/kernel/mutex.h`: a mutex in static storage, as `mutex_init` leaves
  one; `p` is its own address, an address constant, from which the lists point to themselves.
- **`nova-kcore`**:
  - In C (`kcore_selftest.c`): a static mutex made by `MUTEX_INIT_AT` is compared member by member with one from
    `mutex_init` (each list head pointing to itself), then locked and unlocked.
  - In Nova (`kcore_test.nova`): a static `Mutex<u64>`, taken twice (check 10); a static `ObjectCache<Tracked>`, set
    up, a value allocated in it and read back (11), and the box's drop dropping the value once (12).
- **The analyzer baseline**: the four `kcore_test.c` entries are gone; the analysis is clean without them.
- `docs/build/nova.md` (the library's static mutex and object cache), a history entry.

## The bug the first boot found

With novac 0.3.0, check 11 failed on both architectures: `ObjectCache.setUp` passed `Tracked`'s alignment, 8, and
`cache_setup` refuses one below `KMALLOC_MIN_ALIGN`. Every type aligned below 16 was affected. Nova's library now
passes 0 for alignments up to 16, which asks for the minimum (16 meets any smaller alignment); a boot with the fixed
library passed. Nova released the fix alone as 0.3.1, from its `release-0.3` branch (Nova `docs/release.md`, "Point
releases"). Nova's own check of the library against these headers (`k3.py`) only compiles, so it could not see this.

## Not covered

- The self-test runs on one thread; the object cache and static mutex are not yet used from several CPUs.
- An object cache of a type holding C state is not possible in v1 (Nova ADR 0027 §6).
